Système de Bâtiments — Namespace GAME (Unity / C#) Doc de synthèse destinée à une IA : architecture, intentions de conception, flux, pièges. Si l'IA cible a aussi accès au code source, la section « Référence des classes » peut être allégée. 1. Contexte projet Jeu de gestion / construction (city-builder) : bâtiments civils, économiques, militaires, religieux ; habitants/ouvriers = Unit ; ressources gérées via des Storage ; cycle jour/nuit (TimeManager, DailyUpdate, lumières nocturnes) ; sauvegarde par séralisation manuelle. Namespace GAME. Dépendances externes non détaillées ici : Unit, Storage, Player, MyTerrain, ConstructionModule, TimeManager, Configuration*, UIWindowStack, GameObjectUI, UILanguage. 2. Intentions de conception Composition plutôt qu'héritage : pas de sous-classe de Building par type de bâtiment (~60 types). Les bâtiments se construisent par assemblage de BuildingModule dans des BuildingSlot. Double stockage : ConstructionStorages (temporaires, pour le chantier) vs Storages (permanents, créés à la fin de construction). Les modules réservent des stockages via GetStorage — réservation/dé-reservation explicites, pas de magie. UI deux niveaux : compacte dans le monde (BuildingUI + UIBuildingModule, suit le bâtiment en 3D) et détaillée en fenêtre (UIWindowBuildingModulesContainer + UIWindowBuildingModule). Validation différée : un panneau de module peut exiger OK/Cancel (NeedValidation → Apply/Cancel). i18n par clés : Title = clé de traduction rendue via UILanguage — jamais de texte brut. Gestion du temps en ticks : DailyUpdate (journalier) + Work (frame) — deux rythmes distincts. 3. Cycle de vie d'un bâtiment (flux maître) text InitializePlacement() → Status = PLACEMENT (active uniquement "Building") ├─ PlacementAuthorized(terrain, ref target, ref rotate) → validité ├─ PlacementAuthorizedCoast(terrain, rect) → contraintes de côte └─ CancelPlacement() InitializeContruction() → Status = CONSTRUCTION ├─ crée les ConstructionStorages, installe constructionModule ├─ chaque frame : Building.Work() → constructionModule.Work() + InfoWindow.Work() │ ⚠ les modules ne tournent PAS pendant la construction └─ CancelConstruction() → OnConstructionCanceled ConstructionDone() → Status = COMPLETE ├─ détruit tous les enfants SAUF "Building", "Obstacles", "Persistent" (par NOM) ├─ détruit les stockages de chantier, crée les stockages permanents └─ InitializeModules() → InstallModule(slot, prefab) → module.Install(building) (crée l'UI compacte de chaque module dans Building.UI) Remove() → détruit stockages, désinstalle modules, Destroy(gameObject) Une fois complet, Work() gère : sorties d'unités → module.Work() sur chaque module → InfoWindow.Work(). 4. Carte des dépendances text Building ├── BuildingSlot Modules (List : prefabs) + Module (instance installée) │ └── BuildingModule │ ├── Storage (réservés via Building.GetStorage) │ ├── UIBuildingModule (UI compacte, monde) │ └── UIWindowBuildingModule (UI détaillée, fenêtre) ├── BuildingUI contient les UIBuildingModule, suit le bâtiment ├── InfoWindowBuilding LEGACY — partiellement remplacée par le container └── UIWindowBuildingModulesContainer └── UIWindowBuildingModule (créés via BuildingModule.CreateDetailedUI) 5. Référence des classes 5.1 Building : MonoBehaviour Rôle : classe centrale — état, placement, construction, unités, stockages, modules, UI, persistance. 🛠️ État clé : Status, Type, Enable, Player, Terrain, Slots, Storages, ConstructionStorages, InUnits/ExitingUnits, UI, InfoWindow, constructionModule, Area/PersistentCircle, ID/ConfigID, EmissiveObjects/NightLights. ⚙️ API (regroupée par thème) Cycle : InitializePlacement / InitializeContruction / ConstructionDone / CancelConstruction / Remove Modules : InitializeModules / InstallModule(slot, prefab) Stockages : GetStorage(RESOURCE) / GetConstructionStorage() / FreeStoragesCount() / UnreserveAllStorages / DestroyAllStorages Unités : UnitEnter / UnitExit / UnitExitImemdiatly / UnitDie / WorkersList() / ActiveTaches() Visuel : MaterialsColor / MaterialsHeight / UpdateVisual / DailyUpdate / SetProductionSpeed Zone : ShowTerrainCircle / SetPersistentCircle / InArea Persistance : Serialize / PreDeserialize / Deserialize Callbacks : OnMouseClick / OnYes / OnEscape / OnSecondaryBuildingDone / InfoWindowCallBack Enums du fichier : BUILDING_STATUS { NONE, PLACEMENT, CONSTRUCTION, COMPLETE } BUILDING_CATEGORIES { OTHER, CIVILIAN, ECONOMIC, MILITARY, RELIGIOUS, DECORATION, TOURISM } BUILDING : ~60 types, IDs non contigus (TENT=50, OBELISK_1=100…) — ne jamais supposer de continuité. ⚠️ Pièges Modules muets pendant la construction (voir §3). ConstructionDone() purge la hiérarchie par nom — un enfant renommé hors de la liste protégée sera détruit. GetStorage() retourne null si rien de libre → à gérer côté appelant. Tout état persistant doit passer par Serialize/PreDeserialize/Deserialize. 5.2 BuildingSlot / BuildingModule BuildingSlot (sérialisable) : List Modules (prefabs candidats) + BuildingModule Module (instance installée). BuildingModule : classe de base des composants installables. 🛠️ UI (prefab compact) / UIWindow (prefab détaillé) / Building / Storages ⚙️ Install(building) (attache + UI compacte ; ne fait rien si prefab null) / Uninstall() (libère stockages + retire l'UI) / Work() / GetStorage(resource, type, priority, fixedPriority, max) / CreateDetailedUI(container) ⚡ Flux : Install est appelé par Building.InstallModule après ConstructionDone. CreateDetailedUI est appelé à l'ouverture de la fenêtre d'info, pas à l'install. ⚠️ Classification par MODULE_TYPE { OCCUPANCY, STORAGE, WORKSHOP, DEFENSE, EXTENSION }. 5.3 BuildingUI : GameObjectUI, UILanguage UI monde : convertit la position 3D de UIPivotPoint en écran à chaque Update, contient les UIBuildingModule. AddModule/RemoveModule → RearrangeModules (réordonne le layout à chaque changement). 5.4 UIWindowBuildingModulesContainer : UIWindowStack Fenêtre d'info détaillée d'un bâtiment. InitializeContainer(building) : lie le bâtiment, active OK/Cancel si un module a NeedValidation() == true Open(p) : force le rebuild des layouts dans l'ordre enfants → conteneur → panel avant base.Open (la taille de la fenêtre dépend du contenu réel) CloseWindow(evt) : YES → Apply() sur tous les modules ; NO → Cancel() 5.5 InfoWindowBuilding : UIWindowStack, UILanguage ⚠️ Legacy — activation/désactivation du bâtiment + toggle du cercle persistant. Partiellement remplacée par 5.4 : vérifier les usages avant modification ou suppression. 5.6 UIBuildingModule : MonoBehaviour UI compacte d'un module, vit dans BuildingUI. Initialize(module) assigne la référence. 5.7 UIWindowBuildingModule : MonoBehaviour, UILanguage Base des panneaux détaillés dans la fenêtre 5.4. NeedValidation() (défaut false — surcharger pour activer OK/Cancel) / Apply() / Cancel() / Initialize(module) (enregistre le handler de langue) / Title = clé i18n. 6. Check-list : créer un nouveau module Sous-classer BuildingModule, choisir son MODULE_TYPE Overrider Work() ; appeler GetStorage(...) pour réserver (gérer le null) Assigner le prefab UI compacte (UI) et le prefab panneau (UIWindow) Si validation requise : NeedValidation() → true + overrider Apply/Cancel Ajouter le prefab aux Modules d'un BuildingSlot — l'install est géré par InitializeModules État persistant ⇒ gérer dans Serialize/PreDeserialize/Deserialize 7.
