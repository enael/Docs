# Résumé global du code C# – Namespace GAME ## 0. Métadonnées - Langage : C# - Framework : Unity - Namespace : GAME - Fichiers analysés : - `Building.cs` - `BuildingModule.cs` (inclut `BuildingSlot`) - `BuildingUI.cs` - `UIWindowBuildingModulesContainer.cs` - `InfoWindowBuilding.cs` - `UIBuildingModule.cs` - `UIWindowBuildingModule.cs` - Date : 2026-09-11 ## 1. Vue d’ensemble Ce code implémente un système de bâtiments pour un jeu Unity. Un `Building` est un MonoBehaviour qui gère : - son cycle de vie : placement, construction, complet ; - ses unités (`Unit`) ; - ses stockages (`Storage`) permanents et de construction ; - ses modules (`BuildingModule`) installés dans des `BuildingSlot` ; - son UI dans le monde (`BuildingUI`) et ses fenêtres d’information (`UIWindowBuildingModulesContainer`, `InfoWindowBuilding`). Les modules (`BuildingModule`) sont des composants attachés à un bâtiment. Ils peuvent réserver des stockages, exécuter une logique (`Work`), et générer une UI détaillée dans la fenêtre d’information. ## 2. Table des matières 1. Building.cs 2. BuildingModule.cs 3. Notes et pièges Building.Work ne fait rien pour les modules si le bâtiment est en construction : c’est constructionModule.Work() qui est appelé. Building.ConstructionDone détruit tous les enfants sauf "Building", "Obstacles", "Persistent". Il recrée ensuite les stockages permanents et initialise les modules. BuildingModule.Install instancie UI et l’ajoute à Building.UI. Si UI est null, rien n’est fait. BuildingModule.GetStorage retourne null si aucun stockage libre n’est trouvé. UIWindowBuildingModulesContainer.Open force la reconstruction des layouts pour que la fenêtre s’adapte à la taille réelle des modules. UIWindowBuildingModule.NeedValidation retourne false par défaut. Surcharger pour activer les boutons OK/Cancel. InfoWindowBuilding semble être une ancienne fenêtre d’information, remplacée partiellement par UIWindowBuildingModulesContainer. Vérifier les usages avant modification.
